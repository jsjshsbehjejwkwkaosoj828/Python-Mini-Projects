# Contributing

Thank you for your interest in improving Python Mini Projects.

## Before making a change

- Check the existing project README and setup instructions.
- Keep each change focused on one improvement.
- Preserve existing application behavior unless the change explicitly requires otherwise.
- Avoid committing virtual environments, cache directories, local databases, or personal data.

## Development workflow

1. Fork the repository or create a feature branch.
2. Make the change in the relevant project directory.
3. Run the application or the most relevant available checks.
4. Update documentation when commands, dependencies, or behavior change.
5. Open a pull request with a clear summary and validation notes.

## Pull request checklist

- [ ] The change has a clear purpose.
- [ ] Existing project structure and conventions are respected.
- [ ] No secrets, credentials, or personal data are included.
- [ ] Relevant tests or manual checks have been performed.
- [ ] Documentation is updated when needed.

## Reporting issues

When reporting a bug, include the affected project, steps to reproduce it, expected behavior, actual behavior, and relevant error output. Remove private information before sharing logs.

Thank you for helping make the projects more reliable.
